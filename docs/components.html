Buttons

Combine a base class with color, size, outline, pill, block, icon, and loading modifiers.

<button class="ui-btn ui-btn-primary">Primary</button>
<button class="ui-btn ui-btn-secondary">Secondary</button>
<button class="ui-btn ui-btn-success">Success</button>
<button class="ui-btn ui-btn-info">Info</button>
<button class="ui-btn ui-btn-outline-primary">Outline</button>
<button class="ui-btn ui-btn-primary ui-btn-pill">Pill</button>
<button class="ui-btn ui-btn-primary ui-btn-loading">Loading</button>

More button variants

Every color has an ui-btn-outline-* counterpart (primary/secondary/success/danger shown here); ui-btn-square removes rounding; ui-btn-group joins adjacent buttons into one connected control (a common toolbar/segmented-control pattern).

<button class="ui-btn ui-btn-outline-danger">Outline danger</button>

<div class="ui-btn-group" role="group">
  <button class="ui-btn ui-btn-outline-secondary">Day</button>
  <button class="ui-btn ui-btn-outline-secondary ui-active">Week</button>
  <button class="ui-btn ui-btn-outline-secondary">Month</button>
</div>

Sizes & layout

ui-btn-sm and ui-btn-lg resize the control; ui-btn-block stretches it to the full width of its container; ui-btn-icon makes a square, icon-only button (pair it with an aria-label since there's no visible text).

<button class="ui-btn ui-btn-sm ui-btn-primary">Small</button>
<button class="ui-btn ui-btn-primary">Default</button>
<button class="ui-btn ui-btn-lg ui-btn-primary">Large</button>
<button class="ui-btn ui-btn-icon ui-btn-outline-secondary" aria-label="Add item">+</button>
<button class="ui-btn ui-btn-primary ui-btn-block">Block button</button>

Floating labels

The label starts as a placeholder and floats up on focus or once the field has a value. Requires placeholder=" " (a single space) on the input so :placeholder-shown works, and the label must come after the input in markup. .ui-floating-outline floats the label directly onto the border instead of into the padding.

<div class="ui-floating">
  <input class="ui-control" id="floatName" placeholder=" ">
  <label class="ui-label" for="floatName">Full name</label>
</div>

<div class="ui-floating ui-floating-outline">
  <input class="ui-control" id="floatEmail" placeholder=" ">
  <label class="ui-label" for="floatEmail">Email address</label>
</div>

Checkboxes, radios, and switches

Custom controls are label-based and coexist with global legacy checkbox rules. The label must immediately follow the input.

       class="ui-checkbox ui-checkbox-lg ui-checkbox-success"
       type="checkbox">
<label for="check1">Large success checkbox</label>

<input id="switch1" class="ui-switch ui-switch-primary" type="checkbox">
<label for="switch1">Enable notifications</label>

Multi-select with checkboxes

Enhance a native multiple select. The original select remains in the form and receives selected values. In tags display mode, selecting more than data-max-tags (default 3) collapses the rest into a single "+N" chip so the trigger doesn't grow unbounded — try "Select all" below.

<select name="officersIds"
        multiple
        data-ui-multiselect
        data-display="tags"
        data-max-tags="3"
        data-placeholder="Select officers"
        data-search="true"
        data-select-all="true">
  <option value="1">Asha M.</option>
  <option value="2">Baraka J.</option>
</select>

Date range

A two-month calendar popover with quick presets, built over two native <input type="date"> fields so the chosen range still posts with a plain HTML form. Supports full keyboard navigation (arrow keys, Home/End, Page Up/Down, Enter), data-min-date/data-max-date bounds, data-disabled-dates, and a clear button — smart-positioned so it flips above the field and escapes clipping when opened near the edge of the screen or inside a scrollable container.

<div class="ui-date-range" data-ui-date-range
     data-ui-placeholder="Select date range"
     data-min-date="2026-01-01"
     data-max-date="2026-12-31"
     data-disabled-dates="2026-12-25,2026-01-01">
  <input type="date" name="reportStart" aria-label="Start date">
  <input type="date" name="reportEnd" aria-label="End date">
</div>

<script>
document.querySelector("[data-ui-date-range]")
  .addEventListener("ui:daterange:change", function (event) {
    console.log(event.detail.start, event.detail.end);
  });
</script>

Prefer a single form field over two? Wrap just one <input> instead of two — the component detects this and stores the range as one machine-parseable value (YYYY-MM-DD - YYYY-MM-DD) in it. Use type="text", since a native type="date" input can only ever hold a single date and would silently reject the combined value.

<div class="ui-date-range" data-ui-date-range>
  <input type="text" name="reportRange">
</div>
<!-- posts as reportRange=2026-07-20 - 2026-07-26 -->

Date picker

The single-date counterpart to the date range picker: one month, one native <input type="date">, and simple Yesterday/Today/Tomorrow presets. Shares the same keyboard navigation, positioning, data-min-date/data-max-date/data-disabled-dates, and clear button as the range picker.

<div class="ui-date-picker" data-ui-date-picker
     data-ui-placeholder="Select date">
  <input type="date" name="inspectionDate" aria-label="Inspection date">
</div>

<script>
document.querySelector("[data-ui-date-picker]")
  .addEventListener("ui:datepicker:change", function (event) {
    console.log(event.detail.value);
  });
</script>

Save draft

Add data-ui-draft to autosave form input to localStorage as the user types (debounced). If a draft exists next time the page loads, a banner offers to restore or discard it. The draft clears itself on submit. Type something below, then reload this page to see the restore banner.

<form data-ui-draft data-ui-draft-key="inspection-form">
  <div class="ui-form-group">
    <label class="ui-label" for="notes">Inspection notes</label>
    <textarea class="ui-control" id="notes" name="notes"></textarea>
  </div>
  <button type="submit">Submit</button>
  <span data-ui-draft-status></span>
</form>

<!-- ui:draft:saved / ui:draft:restored / ui:draft:discarded fire on the form -->

Confirm dialog

A promise-based confirmation modal for destructive actions, replacing window.confirm(). Reuses the modal's focus trap, Escape handling, and backdrop click.

UI.confirm({
  title: "Revoke licence",
  message: "This will immediately revoke the operator licence. " +
           "This cannot be undone.",
  variant: "danger",
  confirmText: "Revoke licence"
}).then(function (confirmed) {
  if (confirmed) {
    // proceed with the revoke request
  }
});

Confirm dialog classes reference

UI.confirm() is JavaScript-only — it builds and renders a .ui-modal.ui-modal-sm for you, reusing every class from the Modal reference above. There are no additional classes to write by hand.
