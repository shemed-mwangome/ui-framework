Form validation

Add data-ui-validate to a form. Native constraints (required, type, pattern, min/max) are checked alongside cross-field rules, and messages render inline instead of in a native browser bubble — which cannot be styled, is not read out on submit, and disappears on scroll.

The primary pattern is per-field: a red border on the control and a short message directly beneath it. The error summary below is optional — add data-ui-validate-summary only on longer forms where a single at-a-glance list and jump-links genuinely help; leave it out and the field-level highlighting still works on its own.

<form data-ui-validate action="/save" method="post">
  <div data-ui-validate-summary></div>

  <div class="ui-field">
    <label class="ui-label" for="email">Email</label>
    <input class="ui-control" id="email" name="email" type="email" required>
  </div>

  <div class="ui-field">
    <label class="ui-label" for="end">End date</label>
    <input class="ui-control" id="end" name="end" type="date" data-ui-rule-after="start">
  </div>

  <button class="ui-btn ui-btn-primary" type="submit">Submit</button>
</form>

Binding server errors

The piece that otherwise gets hand-written on every screen: take a failed POST's JSON and put each message on the right control, in the summary, with focus moved.

fetch("/save", { method: "POST", body: new FormData(form) })
  .then(function (response) { return response.json(); })
  .then(function (data) {
    if (data.errors) {
      // { "taxId": "Already registered", "name": ["Name is taken"] }
      UI.validate.showErrors(form, data.errors);
    }
  });

Input masks

data-ui-mask formats as the user types. Pattern masks use 9 for a digit, A for a letter and * for either; anything else is a literal the mask inserts. Numeric and currency masks group thousands for the active locale. The caret keeps its place across reformatting, including mid-string edits.

<input class="ui-control" data-ui-mask="999-999-999">
<input class="ui-control" data-ui-mask="+99 999 999 999">
<input class="ui-control" data-ui-mask="AAA-9999">

<!-- Post the raw digits while the user still sees the formatting -->
<input class="ui-control" name="amount"
       data-ui-mask="currency"
       data-ui-currency="USD"
       data-ui-decimals="2"
       data-ui-mask-raw="true">

Combobox

Type-ahead over a single <select>, filtering in place or querying an endpoint. The backing <select> stays in sync, so the field posts normally in a server-rendered form and validation still sees it.

<!-- Filter options already in the DOM -->
<select name="parent" data-ui-combobox data-ui-placeholder="Search companies">
  <option value=""></option>
  <option value="1">Acme Holdings Ltd</option>
</select>

<!-- Or query a server. The endpoint receives ?q=<term> and returns
     [{value, label, hint}] or {results: [...]} -->
<select name="customer" data-ui-combobox
        data-ui-url="/api/customers"
        data-ui-min-chars="2"></select>

Date range

A two-month calendar popover with quick presets, built over two native <input type="date"> fields so the chosen range still posts with a plain HTML form. Supports full keyboard navigation (arrow keys, Home/End, Page Up/Down, Enter), data-min-date/data-max-date bounds, data-disabled-dates, and a clear button — smart-positioned so it flips above the field and escapes clipping when opened near the edge of the screen or inside a scrollable container.

Like ui-select/ui-control, the trigger is width: 100% by default — it fills whatever column it's placed in, the same way a native form field would, so it lines up with its neighbours in a grid row instead of shrinking to its own content. That's the right default inside a form, but wrong for a standalone field with nothing to line up with (a toolbar filter, a compact "as of" date next to a page title) — the demo below is deliberately narrowed to 20rem to show that shape; without a surrounding grid column it would otherwise stretch to the full width of whatever container it sits in, however wide that happens to be. Add ui-date-range-inline to size to content instead:

<!-- default: fills its column, e.g. ui-col-md-4 alongside other fields -->
<div class="ui-date-range" data-ui-date-range
     data-ui-placeholder="Select date range"
     data-min-date="2026-01-01"
     data-max-date="2026-12-31"
     data-disabled-dates="2026-12-25,2026-01-01">
  <input type="date" name="reportStart" aria-label="Start date">
  <input type="date" name="reportEnd" aria-label="End date">
</div>

<script>
document.querySelector("[data-ui-date-range]")
  .addEventListener("ui:daterange:change", function (event) {
    console.log(event.detail.start, event.detail.end);
  });
</script>
<!-- ui-date-range-inline: sizes to its own content, sits anywhere -->
<div class="ui-date-range ui-date-range-inline" data-ui-date-range>
  <input type="date" name="asOfStart">
  <input type="date" name="asOfEnd">
</div>

Prefer a single form field over two? Wrap just one <input> instead of two — the component detects this and stores the range as one machine-parseable value (YYYY-MM-DD - YYYY-MM-DD) in it. Use type="text", since a native type="date" input can only ever hold a single date and would silently reject the combined value.

<div class="ui-date-range" data-ui-date-range>
  <input type="text" name="reportRange">
</div>
<!-- posts as reportRange=2026-07-20 - 2026-07-26 -->

Save draft

Add data-ui-draft to autosave form input to localStorage as the user types (debounced). If a draft exists next time the page loads, a banner offers to restore or discard it. The draft clears itself on submit. Type something below, then reload this page to see the restore banner.

<form data-ui-draft data-ui-draft-key="review-form">
  <div class="ui-form-group">
    <label class="ui-label" for="notes">Review notes</label>
    <textarea class="ui-control" id="notes" name="notes"></textarea>
  </div>
  <button type="submit">Submit</button>

Tree select

A checkbox hierarchy for bulk-select trees — region → supplier → site, category → team → member, anywhere selecting a whole branch at once needs to be as easy as selecting one leaf. Checking a row cascades the check to every descendant; checking or unchecking a descendant rolls back up to a tri-state (checked / unchecked / indeterminate) ancestor checkbox, the same way a native file-tree or permissions UI behaves. Expand/collapse is independent of selection — click anywhere on a row to toggle it, or its dedicated arrow. A disabled leaf (something already actioned, or not eligible) is excluded from both the cascade and its ancestors' tri-state, so it can never get silently swept into a "select all."
